## ADDED Requirements

### Requirement: 用户可以使用邮箱和密码登录
系统MUST允许已注册用户通过邮箱和密码登录系统。

#### Scenario: 成功使用邮箱登录
- **WHEN** 用户在登录页面输入已注册的邮箱地址
- **WHEN** 用户输入正确的密码
- **WHEN** 用户点击"登录"按钮
- **THEN** 系统验证邮箱是否存在
- **THEN** 系统使用bcrypt验证密码是否正确
- **THEN** 系统创建用户会话（使用Reflex内置会话管理）
- **THEN** 系统更新AuthState中的认证状态为已登录
- **THEN** 系统跳转到首页
- **THEN** 系统显示登录成功的提示信息

#### Scenario: 使用不存在的邮箱登录
- **WHEN** 用户在登录页面输入不存在的邮箱地址
- **WHEN** 用户输入任意密码
- **WHEN** 用户点击"登录"按钮
- **THEN** 系统显示"邮箱或密码错误"的错误提示
- **THEN** 系统不创建会话
- **THEN** 用户停留在登录页面
- **THEN** 系统不透露邮箱是否存在的具体信息（防止枚举攻击）

#### Scenario: 使用错误的密码登录
- **WHEN** 用户在登录页面输入已注册的邮箱地址
- **WHEN** 用户输入错误的密码
- **WHEN** 用户点击"登录"按钮
- **THEN** 系统显示"邮箱或密码错误"的错误提示
- **THEN** 系统不创建会话
- **THEN** 用户停留在登录页面

#### Scenario: 登录时邮箱格式无效
- **WHEN** 用户在登录页面输入无效的邮箱地址
- **WHEN** 用户点击"登录"按钮
- **THEN** 系统显示"邮箱格式无效"的错误提示
- **THEN** 系统不创建会话
- **THEN** 用户停留在登录页面

- **WHEN** 用户点击"登录"按钮

- **THEN** 系统使用bcrypt验证密码是否正确

- **WHEN** 用户输入任意密码
- **WHEN** 用户点击"登录"按钮

### Requirement: 系统必须防止暴力破解登录攻击
系统MUST实施rate limiting以防止恶意用户通过自动化脚本尝试多个密码。

#### Scenario: 用户在短时间内多次尝试登录
- **WHEN** 用户在1分钟内尝试登录超过5次
- **THEN** 系统显示"登录尝试过于频繁，请稍后再试"的错误提示
- **THEN** 系统拒绝后续的登录请求
- **THEN** 用户等待1分钟后才能继续登录

### Requirement: 登录表单必须提供实时验证反馈
系统MUST在用户输入时提供实时的表单验证反馈。

#### Scenario: 用户输入邮箱时实时验证
- **WHEN** 用户在邮箱输入框中输入内容
- **THEN** 系统实时验证邮箱格式
- **THEN** 如果邮箱格式无效，显示"邮箱格式无效"的提示
- **THEN** 如果邮箱格式有效，显示绿色的勾选标记

### Requirement: 登录成功后系统必须记住用户状态
系统MUST在登录成功后保持用户的认证状态，直到用户登出或会话过期。

#### Scenario: 用户登录后刷新页面
- **WHEN** 用户成功登录
- **WHEN** 用户刷新页面
- **THEN** 系统保持用户的认证状态
- **THEN** 用户仍然处于已登录状态
- **THEN** 用户可以访问需要认证的页面

#### Scenario: 用户登录后关闭浏览器再打开
- **WHEN** 用户成功登录
- **WHEN** 用户关闭浏览器
- **WHEN** 用户重新打开浏览器并访问网站
- **THEN** 系统保持用户的认证状态（如果会话未过期）
- **THEN** 用户仍然处于已登录状态
