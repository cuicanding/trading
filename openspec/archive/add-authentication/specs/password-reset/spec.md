## ADDED Requirements

### Requirement: 用户可以请求密码重置
系统MUST允许用户通过注册的邮箱请求密码重置。

#### Scenario: 成功请求密码重置
- **WHEN** 用户在密码重置页面输入已注册的邮箱地址
- **WHEN** 用户点击"发送重置链接"按钮
- **THEN** 系统验证邮箱是否存在
- **THEN** 系统使用secrets模块生成安全的重置token
- **THEN** 系统在password_reset_tokens表中创建token记录（设置1小时过期时间）
- **THEN** 系统发送包含重置链接的邮件到用户邮箱
- **THEN** 系统显示"密码重置链接已发送到您的邮箱"的提示信息
- **THEN** 用户停留在当前页面或跳转到登录页面

#### Scenario: 请求重置不存在的邮箱
- **WHEN** 用户在密码重置页面输入不存在的邮箱地址
- **WHEN** 用户点击"发送重置链接"按钮
- **THEN** 系统显示"如果该邮箱已注册，重置链接将发送到您的邮箱"的提示信息
- **THEN** 系统不透露邮箱是否存在的具体信息（防止枚举攻击）
- **THEN** 系统不发送邮件
- **THEN** 用户停留在当前页面

#### Scenario: 请求重置时邮箱格式无效
- **WHEN** 用户在密码重置页面输入无效的邮箱地址
- **WHEN** 用户点击"发送重置链接"按钮
- **THEN** 系统显示"邮箱格式无效"的错误提示
- **THEN** 系统不生成token
- **THEN** 系统不发送邮件
- **THEN** 用户停留在当前页面

### Requirement: 用户可以使用重置链接设置新密码
系统MUST允许用户通过邮件中的重置链接设置新密码。

#### Scenario: 成功使用重置链接设置新密码
- **WHEN** 用户点击邮件中的重置链接
- **THEN** 系统验证token是否存在且未过期
- **THEN** 系统验证token是否已被使用
- **THEN** 系统显示密码重置页面
- **WHEN** 用户输入新密码
- **WHEN** 用户再次输入确认密码
- **WHEN** 用户点击"重置密码"按钮
- **THEN** 系统验证两次输入的密码是否一致
- **THEN** 系统验证新密码强度是否符合要求
- **THEN** 系统更新users表中的password_hash字段
- **THEN** 系统标记password_reset_tokens表中的token为已使用
- **THEN** 系统清除用户的所有会话（强制用户重新登录）
- **THEN** 系统跳转到登录页面
- **THEN** 系统显示"密码重置成功，请使用新密码登录"的提示信息

#### Scenario: 使用已过期的重置链接
- **WHEN** 用户点击已过期的重置链接
- **THEN** 系统检测到token已过期
- **THEN** 系统显示"重置链接已过期，请重新请求"的错误提示
- **THEN** 系统跳转到密码重置请求页面

#### Scenario: 使用已被使用的重置链接
- **WHEN** 用户点击已被使用的重置链接
- **THEN** 系统检测到token已被使用
- **THEN** 系统显示"重置链接已失效，请重新请求"的错误提示
- **THEN** 系统跳转到密码重置请求页面

#### Scenario: 使用无效的重置链接
- **WHEN** 用户访问无效的重置链接（token不存在）
- **THEN** 系统检测到token不存在
- **THEN** 系统显示"重置链接无效，请重新请求"的错误提示
- **THEN** 系统跳转到密码重置请求页面

#### Scenario: 重置密码时两次输入不一致
- **WHEN** 用户在密码重置页面输入新密码
- **WHEN** 用户输入与第一次不同的确认密码
- **WHEN** 用户点击"重置密码"按钮
- **THEN** 系统显示"两次输入的密码不一致"的错误提示
- **THEN** 系统不更新密码
- **THEN** 用户停留在密码重置页面

#### Scenario: 重置密码时新密码强度不足
- **WHEN** 用户在密码重置页面输入强度不足的新密码
- **WHEN** 用户输入确认密码
- **WHEN** 用户点击"重置密码"按钮
- **THEN** 系统显示"密码强度不足，至少需要8位且包含字母和数字"的错误提示
- **THEN** 系统不更新密码
- **THEN** 用户停留在密码重置页面

### Requirement: 系统必须防止频繁请求密码重置
系统MUST实施rate limiting以防止恶意用户滥用密码重置功能。

#### Scenario: 用户在短时间内多次请求密码重置
- **WHEN** 用户在1分钟内对同一邮箱请求密码重置超过3次
- **THEN** 系统显示"请求过于频繁，请稍后再试"的错误提示
- **THEN** 系统拒绝后续的请求
- **THEN** 用户等待1分钟后才能继续请求

### Requirement: 密码重置邮件必须包含必要信息
系统MUST在密码重置邮件中包含所有必要的信息和清晰的指导。

#### Scenario: 查看密码重置邮件内容
- **WHEN** 系统发送密码重置邮件
- **THEN** 邮件标题为"重置您的密码"
- **THEN** 邮件内容包含用户友好的问候语
- **THEN** 邮件内容包含密码重置链接（完整的URL）
- **THEN** 邮件内容说明链接的有效期（1小时）
- **THEN** 邮件内容说明如果用户未请求重置，可以忽略此邮件
- **THEN** 邮件内容包含系统名称和支持联系方式

### Requirement: 密码重置表单必须提供实时验证反馈
系统MUST在用户输入时提供实时的表单验证反馈。

#### Scenario: 用户输入新密码时实时验证
- **WHEN** 用户在新密码输入框中输入内容
- **THEN** 系统实时验证密码强度
- **THEN** 显示密码强度指示器（弱/中/强）
- **THEN** 如果密码强度不足，显示具体要求（如"还需要1个数字"）

#### Scenario: 用户输入确认密码时实时验证
- **WHEN** 用户在确认密码输入框中输入内容
- **THEN** 系统实时比较两次输入的密码
- **THEN** 如果两次输入不一致，显示"密码不一致"的提示
- **THEN** 如果两次输入一致，显示绿色的勾选标记
